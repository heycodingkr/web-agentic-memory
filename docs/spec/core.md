# CORE: URL·업무 정규화와 공통 데이터 계약

상태: 1차 상세 명세. URL projection과 route scope의 순수 규칙은 `crates/wam-core`에 구현했고, 서버 저장·API 인증·registrable domain 검증은 아직 없다.

## 목적

메모리는 단순한 사이트 전체 팁이 아니라 특정 URL 범위에서 특정 업무를 수행하는 방법이다. 같은 호스트 안에서도 편집 화면, 검색 화면, 업로드 화면은 서로 다른 흐름을 갖는다. 모든 호스트 클라이언트가 같은 URL 정규화와 업무 분류를 써야 recall, 중복 판정, 갱신, 점수 귀속이 일치한다.

## URL 식별 계약

입력 URL은 브라우저의 현재 주소를 사용하되 저장·검색 전에 서버와 클라이언트 양쪽에서 정규화한다. 정규화 결과는 보안상 안전한 라우트 패턴이며 원래 URL 문자열이 아니다.

정규화 순서는 다음과 같다.

1. HTTPS URL만 기본 허용한다. 개발 테스트에서는 loopback 주소만 격리 모드로 허용한다.
2. 사용자 정보, 프래그먼트, 기본 포트, 추적 파라미터를 제거한다. 쿼리 문자열은 키 이름도 기록하지 않는다.
3. 호스트를 소문자 IDNA 형식으로 표준화하고 등록 가능한 공개 도메인인지 검사한다.
4. 경로를 세그먼트로 분리한다. 고정 라우트 단어는 남기고 숫자 ID, UUID, 계정명, 게시물 식별자처럼 보이는 세그먼트는 형식화된 변수로 바꾼다.
5. 동적 세그먼트를 안전하게 분류할 수 없으면 해당 세그먼트를 통째로 제거하거나 호스트 수준으로 후퇴한다. 원본 경로를 저장하지 않는다.
6. 정규화한 host + path pattern + task category로 검색 키를 만든다.

예를 들어 /editor/post/948203?token=abc#content는 호스트와 /editor/post/:id 형태만 남긴다. URL에 이메일이나 토큰이 들어 있거나 정규화가 모호하면 기여 전체를 보류하고 사용자에게 제거 사유를 표시한다.

## 검색 범위와 우선순위

정확 일치 URL 패턴과 업무 카테고리를 가장 먼저 찾는다. 없으면 같은 호스트의 안전한 상위 라우트 패턴, 마지막으로 호스트 전체 적용 메모리를 찾는다. 정확 경로 메모리는 호스트 전용 일반 팁보다 우선한다. 메모리 응답에는 적용 범위와 task category를 포함해 다른 URL로 잘못 적용되지 않게 한다.

같은 호스트의 서로 다른 경로는 자동으로 같은 메모리로 합치지 않는다. 서로 다른 task category도 별도 레코드다. 상위 라우트 메모리를 하위 URL에 적용할 때는 메모리에 적힌 범위가 그 하위 경로를 포함하는지 확인한다. 범위가 모호하면 빈 결과를 반환한다.

## 공통 업무 및 trace 데이터

Contribution은 로그인 사용자, host adapter, 정규화된 URL 패턴, 폐쇄형 task category, 정규화 액션 목록, 결과 카테고리, 명시적 동의 버전, 고유 제출 nonce를 가진다. 액션은 navigate, wait, click, type, key, snapshot, scroll, select, upload, dialog 같은 표준 분류로 변환한다. 호스트 고유 도구 이름은 별도 adapter 표에서 변환하고 알 수 없는 도구는 other로 처리한다.

저장하지 않을 정보는 프롬프트 원문, 입력한 글, 페이지 HTML, 스크린샷, DOM selector, 폼 내용, 쿠키, OAuth 토큰, 전체 URL, 검색어, 문서 제목, 페이지의 개인 식별자다. 업무 의도를 분류하기 위한 task category는 폐쇄 enum으로 저장한다. 추가 설명이 꼭 필요한 경우에는 정해진 짧은 안전 템플릿만 허용한다.

## 요구사항

| ID | 규칙 | 합격 기준 |
|---|---|---|
| F-CORE-01 | URL 정규화는 클라이언트와 서버에서 동일한 결과를 낸다 | 같은 입력의 canonical key가 일치한다 |
| F-CORE-02 | 쿼리·프래그먼트·사용자 정보는 저장하지 않는다 | 입력 센티널이 응답·DB·로그에 없다 |
| F-CORE-03 | 동적 경로 ID는 변수 패턴으로 바꾼다 | 두 계정 ID가 같은 안전 라우트 패턴에 정규화된다 |
| F-CORE-04 | URL + task category가 조회 키다 | 같은 사이트의 다른 URL/업무는 결과가 섞이지 않는다 |
| F-CORE-05 | 정규화 실패는 안전하게 후퇴한다 | 원문 URL 저장 없이 빈 결과 또는 격리 상태가 된다 |
| F-CORE-06 | task category는 폐쇄 enum이다 | 미등록 문자열은 기여 단계에서 거부된다 |
| F-CORE-07 | 도구 action은 host adapter로 표준화한다 | Claude/Codex browser MCP와 Arise 결과가 동일 taxonomy를 쓴다 |
| F-CORE-08 | 승인·교체·폐기된 기록은 버전으로 추적한다 | 이전 버전을 감사·롤백할 수 있다 |

## 연결 테스트

CORE-22~26은 URL 정규화 및 URL 범위 일치를, DEDUP-13~18은 정규화 범위에서 중복과 갱신 결정을, DB-01~19는 해당 키·작성자 귀속·동의 경합·원장과 사용 분석 집계의 저장 제약을 검증한다. SEC-A 및 SEC-D 테스트는 URL, 토큰, 계정 데이터가 로그나 공개 카탈로그로 유출되지 않는지 확인한다.
