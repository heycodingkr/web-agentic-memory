# 측정 기준 수치화 (Metrics & Thresholds)

상태: 초안. **모든 수치는 구현 전에 합의하는 목표값**이고, 측정 후 근거와 함께 조정할 수 있다. 조정할 때는 이 문서를 먼저 고치고 사유를 `변경 이력`에 남긴다. (결과를 보고 기준을 바꾸는 것을 막기 위해, 측정 실행 전에 이 문서를 커밋해 고정한다.)

표기: **게이트** = 미달 시 해당 마일스톤/주장 차단. **목표** = 미달 시 개선 대상, 차단은 아님.

## 1. 성능 이득 벤치 (A/B)

### 1.1 실험 설계

| 항목 | 값 |
|---|---|
| 조건 | T (메모리 없음), M (수동 recall), I (자동 주입) |
| 반복 수 n (조건·태스크당) | fixture/Medium/Naver/Slides: **5**, Flow: **3** (비용 때문, 축소 사실 명시) |
| 최소 n (이 미만이면 "예비 관찰"로만 표기) | 3 |
| 순서 | 조건 교차(블록 무작위), 고정 순서 금지 |
| 비교 단위 | 같은 모델, effort, 프롬프트, 도구 버전, 새 격리 상태 |
| 무효 허용 한도 | 스위트별 무효 run 비율 ≤ **20%**, 초과 시 해당 스위트 결과는 "무효"로 보고 |
| 사전 등록 | 가설, 주 지표, 태스크 목록, 판정 규칙을 실행 **전에** `docs/test/prereg/<날짜>-<suite>.md`로 커밋 |
| 보고 | 모든 run(성공, 실패, 무효)을 공개. 선택적 제외 금지 |

### 1.2 지표와 합격 기준

| 지표 | 정의 | 주장 가능 기준 (README에 "X% 빠르다"라고 쓰려면) |
|---|---|---|
| 제출까지 시간 (TTS) | 첫 도구 호출 → 목적 행동 제출 (저장/생성 요청) | M 또는 I의 **중앙값**이 T 대비 **≥ 20% 감소**, 그리고 **95% 부트스트랩 CI(차이)가 0을 포함하지 않음** |
| 제출까지 도구 호출 수 | 외부 round-trip 수 | 중앙값 **≥ 20% 감소**, CI가 0 미포함 |
| 성공률 | 독립 oracle 기준 | M/I의 성공률이 T보다 **낮지 않음** (n=5 기준 성공 횟수 ≥ T의 성공 횟수). 낮으면 이득 주장 불가 |
| 오류 수 | 도구 오류 + 되돌림 | M/I의 평균이 T보다 **높지 않음** |
| 토큰 순증 | (M/I 총 토큰) − (T 총 토큰) | 힌트 주입 오버헤드 포함 **≤ 0** 이면 "토큰 절감", > 0 이면 증가분을 그대로 보고 |
| 총 시간 (생성 대기 포함) | 제출 후 완료까지 합산 | 참고 지표. 대기 시간은 분리 보고, 메모리 효과로 주장하지 않음 |

주장 등급:

| 등급 | 조건 | README 표기 |
|---|---|---|
| A (확정) | n ≥ 5, 위 기준 모두 충족, 무효 ≤ 20% | "측정: 평균 ±sd, n=5" |
| B (예비) | n = 3~4 또는 CI가 0 포함 | "예비 관찰 (n=3), 일반화 불가" |
| C (관찰) | n < 3 또는 통제 불가 (실사이트 상태 변화) | "관찰 1건, 참고용" |

현재 파일럿(조건당 n=1)은 **C 등급**이다. README의 수치 표는 이 등급 표기를 달고, 반복 측정 후 교체한다.

### 1.3 통계 방법

- 중앙값과 평균±표준편차를 함께 보고한다.
- 차이의 신뢰구간은 **부트스트랩(10,000회 재표본)** 으로 계산한다. n이 작으므로 정규 가정을 쓰지 않는다.
- 다중 비교(태스크 × 조건)가 많으므로, README 헤드라인에 쓰는 지표는 **사전 등록된 주 지표(TTS, 도구 호출 수)** 로 제한한다.
- 이상치는 제거하지 않고 별도 표기한다.

### 1.4 사이트별 목표값 (파일럿 기반 가설, 측정 후 갱신)

| 스위트 | 주 지표 | 가설 (T 대비) | 근거 |
|---|---|---|---|
| BM-FX 리치 에디터 | TTS, 호출 수 | 시간 −40% 이상, 호출 −25% 이상 | 파일럿 −58%, −31% (n=1) |
| BM-FX iframe 에디터 | 호출 수, 오류 | 호출 −30% 이상, 오류 0 | 파일럿 −39%, 3→0 (n=1) |
| Medium | TTS | −30% 이상, 빈 문단 0건 | 파일럿 −48% (n=1) |
| Naver Blog | TTS | −20% 이상 | 파일럿 −30% (n=1, 비통제) |
| Slides 이미지 생성 | 제출까지 호출 수 | −25% 이상 | 가설 (측정 전) |
| Flow 영상 제작 | 제출까지 호출 수 | −25% 이상 | 가설 (측정 전) |

T보다 시간이나 도구 호출이 늘면 메모리를 잘못 만든 것이므로, 원인을 분석해 메모리를 고친 뒤 다시 측정한다.
