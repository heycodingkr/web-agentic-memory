# 이메일 가입·로그인 배포 수용 테스트

2026-11-01 선행 명세. 목표 운영 origin은 `https://webagenticmemory.com`. 제품 계약은 [이메일 인증 명세](../spec/email-auth.md)의 F-EMAIL-01~07, 자동 검사와 이전 실행 결과는 [email-auth.md](email-auth.md)에서 관리한다. 일반 인증 성공 후 My Page(`/dashboard`) 자동 진입과 로그인 이후 기여·랭킹·성과 여정은 [MYPAGE-01~40](my-page.md)에서 이어서 검증한다. 아래는 수용 기준이며 운영 결과는 이 문서의 live spot check와 결과 표에 따로 기록한다. 한 케이스의 일부 관찰은 전체 계정 여정의 통과로 계산하지 않는다.

## 2026년 11월 1일 4090 직접 배포 결과

현재 운영은 Tunnel 없이 4090 서버에 직접 연결한다. 실제 Gmail 수신→최초 이메일 인증→My Page 자동 진입→새로고침 후 세션 유지→로그아웃→두 번째 코드로 기존 계정 로그인까지 확인했다. 두 번째 로그인 후 계정 수는 1개다. DNS·HTTPS·공개 API/MCP·검사 범위와 증거는 [4090 직접 배포 검증](deployment-4090.md)에 기록했다. 아래 초기 read-only 점검의 미실행·실패 기록은 그 당시 빌드에 대한 것이며 현재 전체 EMAIL-PROD 수용 판정으로 재사용하지 않는다. SPF/DKIM 원본 헤더 전체·실기기 Safari·전체 장애/보안 행렬은 별도다.

## 기능 범위

| 사용자 목적 | 제공하는 흐름 |
|---|---|
| 처음 가입 | 이메일 입력 → 코드 수신 → 같은 요청 브라우저에서 코드 검증 → 계정 1개 생성 |
| 기존 계정 로그인 | 같은 화면에서 새 코드 검증 → 기존 계정·프로필·점수로 로그인 |
| 비밀번호 찾기 | 제공하지 않음. 비밀번호가 없으며 메일함에 접근할 수 있으면 새 코드로 재로그인 |
| 메일 미수신/주소 오타 | 수신 주소·스팸함 확인, 재전송 countdown, 주소 다시 입력 |
| 메일함 접근 상실 | 메일 제공자의 복구 안내. 앱의 이메일 변경/소유권 복구·계정 병합은 현재 미지원 |

`가입`과 `로그인`은 사용자 목적에 따라 테스트를 구분하되 같은 인증 경로를 사용한다. 처음 인증할 때 계정이 만들어진다는 안내는 발송 전에 보인다. 신규/기존 여부는 인증 전에 드러내지 않는다.

## 환경·실행 순서

1. **자동 검사**: 기존 EMAIL-01~14, PostgreSQL와 브라우저 검사가 먼저 통과해야 한다. 아래 운영 수용 테스트의 대체 증거로 표시하지 않는다.
2. **예비배포**: 공개 예정 artifact와 동일한 API·웹·PostgreSQL·Redis 구성을 사용한다. 공급자 장애, 시간 경계, 데이터 삭제, replica 동시성은 이 환경에서 재현한다. 실제 운영의 key/시계/DB/Redis를 장애 재현용으로 바꾸지 않는다.
3. **운영**: 실제 HTTPS 도메인과 Resend sender, 소유자가 사용할 수 있는 승인된 실메일함에서 새 시크릿 브라우저 세션으로 실행한다. `resend.dev` 테스트 주소와 mock API는 받은편지함 수신·실사용자 인증의 증거로 인정하지 않는다.
4. 정상 가입/로그인 → 코드/제한 → 세션/보안 → MCP/기기 → 복구 안내 → 브라우저 순서로 검사하고 결과를 남긴다. `운영`으로 지정한 P0가 미실행/차단/실패이면 이메일 인증의 운영 수용 완료로 표시하지 않는다. 예비배포 전용 P0도 해당 환경의 증거가 필요하다.

테스트 수신자는 다음 역할로 나눈다. 실제 주소를 이 공개 문서에 적지 않고 비공개 실행 설정에 매핑한다.

| 역할 | 준비 |
|---|---|
| A | 아직 가입하지 않은 소유한 실메일 주소. 최초 가입 1회를 확인하고 이후 기존 계정으로 사용 |
| B | 이미 가입했고 프로필·점수/기여 기준값을 기록한 테스트 계정 |
| C | 오답·재전송·만료용 별도 소유 주소. A/B의 로그인 검사를 제한 상태로 만들지 않음 |
| D | 삭제/다른 주소·GitHub 구분을 확인할 전용 QA 계정. 일반 사용자 데이터를 사용하지 않음 |

메일 수신은 요청 시각·Resend 접수 시각·실제 수신 시각을 각각 기록한다. 수신 대기 관찰 상한은 2분으로 두고 미수신이면 성공 처리하지 않고 전송 상태·스팸함·DNS를 확인한다. 이는 이번 검사의 관찰 기준이며 서비스 전체의 수신 SLA를 입증하지 않는다. 가입 여부·공개 설정은 운영자에게 허용된 읽기 검사 또는 본인 API로 확인하며, 원문 이메일·인증 코드·session/CSRF/bearer·connection string은 공개 증거에 넣지 않는다.
