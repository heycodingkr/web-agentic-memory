### Meta 코딩 에이전트 호환 작업 (W0-3 후속)

조사 결과에 따라 경로를 고른다.

| 조사 결과 | 선택 경로 |
|---|---|
| MCP 지원 (stdio) | `wam-mcp` stdio 그대로 등록, SMK 전체 수행 |
| MCP 지원 (원격 HTTP만) | 원격 MCP 엔드포인트(`/mcp`)로 연결, 인증 방식 확인 |
| MCP 미지원 | **instruction 경로**: 규칙 파일에 스니펫 + 셸 도구로 `wam recall <host>` 또는 HTTP 호출. 이 경로로 동일 벤치 수행 |
| 환경변수 걸러짐 | 설정에 경로 명시, `status` 도구로 서버가 읽은 경로 확인 (불일치 run 무효) |
| 도구 승인 프롬프트가 매번 뜸 | 비대화형 승인 옵션 확인, 없으면 반자동 절차와 한계를 문서화 |

완료 기준: Meta 에이전트에서 SMK-01~05, 07, 10, 14와 BEH-01, 04를 통과(또는 불가 사유를 근거와 함께 기록).

## 9. 실행 순서 (의존성 기반)

```
W0-1,2,6 ─┐
W0-3(Meta 조사) ─┼─▶ W2-1 (wam-mcp 최소) ─▶ W1-1,2,3,6 (호스트 스모크)
W0-4,5 ───┘         │                               │
                    ├─▶ W6-1,2,3,4 (보안 기반) ──┐   ▼
                    └─▶ W2-2,3,4,6 (연결/배포/가이드)   W1-7 (자발적 호출률)
W3-1..9 (하네스) ──▶ W3-9 검증 통과 ──▶ W8-1 사전 등록 ──▶ W8-2..5 측정 ──▶ W8-7,8
W4-1..5 (fixture/oracle) ─┘                         ▲
W5-1..5 (탐색/메모리 작성) ───────────────────────────┘
W7-1,3 (서버/웹 최소) ─▶ 데모 경로
```

크리티컬 패스: **W0-3 → W2-1 → W1-x → W3-x → W3-9 → W8-1 → W8-x**. 그 사이 W5(메모리 작성)와 W6(보안 기반)은 병렬로 진행한다.

## 11. 최소 데모 범위 (P0 컷)

1. 호스트 2개 이상(Claude Code, Codex)과 Meta 에이전트 호환 결과(통과 또는 불가 사유).

4. 센티널 유출 0건과 악성 힌트 추종 0건의 증거.
5. 링크 연결, 가이드, 리더보드가 보이는 웹 데모.
6. 모든 수치에 n, 등급, 한계를 명시한 README.
